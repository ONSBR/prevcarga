## O modelo (o que o M8 é)

1. **Runtime R-only** = `runtime/{R,rlib,syslib}` + `code/{scripts,models,config}` (**sem** `*/tests/` — testthat é dev-only, M5/M6) + `RUNTIME.json` (`version`, `r_version`, `p3m_snapshot`, `apt_snapshot`, `renv_lock_hash`, `code_commit` (= `prevcarga_code_commit()`, M8.3 Step 8a: o último commit que tocou o **conjunto de paths do `code/`** do M8.1 Step 2 — sem `scripts/tools/`, `scripts/data-prep/`, `*.md`, `*/tests/`, `models/*/models/`; commits só de docs/testes não o mudam), `platform`, `built_at` [lateral], `files[]={path,sha256}` ordenado). `runtime_id` = sha256 do `RUNTIME.json` sem `built_at`. Sem venv/uv/AWS CLI/`ARROW_S3`.
2. **S3 = PONTA externa** (ADR-0016:39): `ci/publish_runtime.sh` usa credencial do host de release; o installer baixa por **HTTPS** só com `curl` — nunca AWS CLI no host do usuário.
3. **Três raízes no host instalado** (fecha a decisão de estado do R1): `PREVCARGA_HOME/versions/<VER>/` (runtime, **imutável**, trocado no upgrade) + `PREVCARGA_HOME/current` (symlink) + **`PREVCARGA_STATE`** (default `~/.local/share/prevcarga`, **fora** de `PREVCARGA_HOME`): registry de produção (`latest`/`v_<hash>`), bundle congelado (combina/k̂), store de backtest, cache/ledger do M7, painel `results/`. O launcher exporta `PREVCARGA_STATE`; `registry.R`/`cache.R`/`orchestrate.R` resolvem suas raízes **a partir dele** (refino da fronteira M1/M5/M7 — §Decisões D12). Upgrade/rollback **nunca tocam** `PREVCARGA_STATE`; `--uninstall` só o remove com `--purge`.
4. **Artefatos treinados** chegam ao `PREVCARGA_STATE` como **pacote de artefatos** separado (`prevcarga-artefatos-<artefatos_id>.tar.zst` + `.sha256`; `artefatos_id` = sha256 do manifesto canônico do pacote **sem o próprio campo `artefatos_id`** — como o `runtime_id` exclui `built_at` —, que lista o `bundle_id` + o `v_<hash>` de cada `(membro,área)` exportado), produzido por `prevcarga registry export` no host de treino, publicado pelo `ci/publish_runtime.sh --artefatos`, instalado por `install.sh --artefatos` com **hash obrigatório** (default de D13; alternativa = staging pelo script Docker externo). ⚠ Só os membros **origem-agnósticos** (`protocol==daily` no `prevcarga_model_spec`, ADR-0011) têm artefato reutilizável; os `retrain_harness` são re-fitados na origem (M8.6) e **não** entram no pacote — a seleção é pelo `protocol`, nunca por lista literal.
5. **Instaladores** em **`install/`** (tier novo — fora de `scripts/`, não entra no `code/` do runtime e não colide com os greps do M1 sobre `scripts/`). Launcher `bin/prevcarga` = pins (`TZ`, `LC_*`, `OMP/OPENBLAS/MKL_NUM_THREADS`, **`VECLIB_MAXIMUM_THREADS`**) + `PREVCARGA_STATE` + `exec "$RT/R/bin/Rscript" --vanilla "$CODE/scripts/prevcarga" "$@"`; o runtime-guard re-assere in-process (ADR-0022).
6. **Windows = WSL2** (ADR-0017 v1): `install.ps1` roda o `install.sh` dentro da distro Ubuntu-22.04; shim `prevcarga.cmd` encaminha p/ o WSL. A tradução de caminho Windows→`/mnt/<x>/` é feita **no lado R** (a fachada normaliza qualquer token com forma de caminho Windows quando `WSL_DISTRO_NAME` está setado) — **sem 2ª lista** de flags fora da gramática.
7. **`verificar`** = integridade → **identidade** → valores por trilho (a identidade bloqueia antes do comparador de valores); modo **`--referencia-legada`** p/ o layout do oráculo (sem run-manifest). **`morning`** = composição fina, gate-0 fail-fast, nunca promove.
8. **A/B por ESTÁGIO**, com referência do oráculo **gerada numa CÓPIA descartável** do oráculo, **com o runtime do próprio oráculo** (R 4.2.3 + mesmo snapshot P3M) e os pins de determinismo, congelada por manifest sha256: A backtest por membro (trilho pela relação máquina+runtime); B reconcile-engine com a **mesma entrada** (os long.parquet por região da combina-A do oráculo) e k̂ re-fitado por origem nos dois lados; C exports byte-copy; D combina propriedade/qualidade; E end-to-end reportado. Veredito por agregador testado por injeção.
