# Estado: gerador de golden do oraculo (P.0f) -- scripts/tools/plugin_golden.R

- Dev-only (Linux, fora do bundle). `Rscript --vanilla scripts/tools/plugin_golden.R --model <m>|_dessem-engine --units <units.yaml> --oracle <dir> [--variant v] [--out d] [--root models] [--data store] [--rscript R] [--format text|json]`. `--root` e `--out` (default `<repo>/.state/golden`) achados pelo caminho do script; nenhuma variavel de ambiente e lida. Sem switch por modelo: roda `<root>/<model>/tests/parity/oracle_driver.R`.
- Contrato do driver: `--oracle <dir> --unit <unit.json> --out <dir> --available-until <ISO>`; grava `native.rds` e `long.parquet` em `--out`. `unit.json` traz a unidade (inclui `oracle_available_until`, `data_dir`).
- `units.yaml`: `units: [{id, area, origin, available_until, weather_issue_cutoff, day0_source, variant?, history_days?, oracle_env?, oracle_cut?}]` + opcionais de topo `tz` (default Etc/GMT+3) e `packages` (pacotes do fingerprint). Invalido => `tools.bad_units` (exit 2) com `where = <unidade>.<campo>`. Funcao reutilizavel: `pc_golden_units(path)`.
- Ambiente do filho = pins (`TZ=UTC`, `LC_ALL=C.UTF-8`, `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`) + `oracle_env` da unidade (inclui `R_LIBS_USER`/biblioteca do oraculo: configuracao, nao literal), via `system2(env=)`; `oracle_cut: start_label` => `--available-until = available_until - 30 min`. O fingerprint de runtime (`pc_runtime_fingerprint`) roda no MESMO Rscript e env do filho.
- Cada unidade roda 2x (cwd e scratch fora do oraculo); `native.rds` `identical` e `long.parquet` byte a byte, senao `tools.oracle_nondeterministic` (repro, exit 12). Saida: `<out>/plugins/<model>/<variant|_>/<area>/<origin>/{native.rds,long.parquet,invocation.json}` (`invocation.json` estavel: scratch como `<scratch>`).
- Preflight: `--out` dentro do oraculo => `tools.out_inside_oracle`; `git status --porcelain` nao vazio => `tools.oracle_dirty`; carimbo de inicio. Ao fim: git status vazio E nenhum arquivo fora de `.git` mais novo que o carimbo, senao `tools.oracle_touched` e o lock NAO e atualizado.
- `golden.lock` (versionado, em `<root>/<model>/tests/parity/`): JSON canonico (chaves ordenadas, LF), por unidade `files` (sha256), `oracle_commit`, `data_digest` (`pc_data_digest`: so as particoes `area_code=/year=` lidas), `fingerprint`. Escrita por tmp + rename. O golden em si (`.state/`) nunca e versionado.
- Observacao: o id `tools.oracle_touched` esta na classe `contract` (exit 2) no catalogo do P.0a; a mensagem de `tools.bad_units` ("Unidades incompativeis") nao descreve este uso (o detalhe vai em `details$why`).
- Testes: `scripts/lib/tests/test-plugin-tools-golden.R` (processo real + oraculo-brinquedo de `helper-plugins.R`: `pc_fake_oracle`, `pc_toy_driver`, `pc_units_two`).
